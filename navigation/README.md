# 地图保存与自主导航

当前实现：版本化地图、AMCL 定位、路径预览，以及监督运行的自动探索建图、
逐点巡检、到点停车检测、异常停车上报、证据归档与本地模型报告。

实车自动行驶尚未验收，也未开放：`navigation_calibration.yaml` 的 `calibrated`
保持 `false`。不能只把这个开关改成 true，必须先完成下面的实测项。

## 已确认和待标定参数

- 用户确认：车长 0.444 m、车宽 0.360 m、前后轴距 0.300 m。
- 现用 `motor_params.yaml` 是 `steer_mode: servo`，后轮等速、前轮舵机转向。
  硬件虽可后轮差速转圈，本版不切换该模式，不使用原地旋转或倒车恢复。
- 待实测：最大有效前轮转角、左右方向、油门与实际车速关系。
- 待核对：`base_link` 相对后轴的位置、雷达相对车身的安装偏移。
- 前轮角度和轮速未经闭环标定，目前的速度换算只是接口实现，不代表控制精度。
- 当前导航使用激光里程计，不依赖本次未完成验收的编码器数据。不能同时启动旧
  `motor_driver` 与 `pwm_proc`，也不能同时发布两路 `odom→base_link`。

## 网页操作

1. 先正常建图，展开地图左上角的“地图与导航”。
2. 输入英文地图名并保存。文件保存到 `~/robot/data/maps/<name>/map.pgm` 和
   `map.yaml`，名称不可覆盖。栅格上下翻转、整数范围和四元数偏航均有回归测试。
3. 解除电机使能，选中地图，点击“加载定位”。这会停止建图管线并启动独占的
   雷达、激光里程计、静态 TF、地图服务、AMCL 和 Nav2；地图服务不做建图。
4. 等“设置当前位置”可用，在地图按下机器人的真实位置，向车头方向拖动并松手。
   初始位姿不能随便选；选错时应重新设置，不应让机器人自行移动找位置。
5. 定位有效后，选择目标并拖出到达朝向。松手只做路径预览，不启用电机。
6. 完成实车标定和开阔地面验收后，当前页面持有驾驶权且已使能时，才允许开始导航。

起点或目标位于障碍内、未知区域、地图外或没有可行路径时，报告失败，不修改地图
来强行通过。桌面和附近物体可能导致起点被占据，需在开阔地面重新建图验证。

## 输出约束

Nav2 的控制器只发布 `/navigation/cmd_vel_raw`，平滑器只发布
`/navigation/cmd_vel_smoothed`；不会直接发布旧驱动使用的 `/cmd_vel`。

仅网页服务将导航指令换算为旧 UDP 契约并送给 `pwm_proc`。必须同时满足：
有效的当前任务、当前驾驶权、使能、标定、定位、TF、扫描和指令新鲜度。
操作页面每 200 ms 续约，600 ms 未收到当前操作者续约则停止并解除使能。
扫描失效、指令超时、定位失效也停止并解除使能，不会在数据恢复后自行续跑。

手动摇杆非零输入和显式清零操作会取消导航。空闲的手动零速心跳不会覆盖自主指令。
急停取消导航并解除使能；失焦、页面隐藏和操作者断线会取消导航。

网页重启会停止其管理的导航进程组。异常退出后，通过记录 PID、进程启动时间和
完整启动路径核验并清理遗留进程，避免两个定位器同时发布 TF。

## AidLux 依赖兼容

板子使用厂商合并包 `aidros-pyenv-ros2-humble`。直接安装官方 Nav2 会使 apt 试图
覆盖该包拥有的 ROS 核心文件，不能使用 `--force-overwrite`。

本次已将 Nav2 及缺失依赖的官方 deb 解压至 `~/robot/deps/nav2`，通过
`navigation_env.sh` 加入搜索路径，厂商库优先。`deps` 不进 Git。
常规网页启动脚本已 source 此环境；手动启动需先 source ROS、lidar_ws、再 source
`~/robot/navigation/navigation_env.sh`。实际参数由 `build_nav_params.py` 基于独立
目录中的 Humble 默认配置生成，不复用其他 ROS 版本的参数文件。

协议和插件依据：[Humble RPP](https://api.nav2.org/nav2-humble/html/md_nav2_regulated_pure_pursuit_controller_README.html)、
[Humble Smac Hybrid](https://api.nav2.org/nav2-humble/html/smac__planner__hybrid_8cpp_source.html)。

## 自动建图与自主巡检工作流（2026-10-14）

地图左上角「地图与导航 → 自动建图与巡检」提供入口，沿用驾驶页面的连接和驾驶权。

1. 解除电机使能、停止当前定位管线，点击「准备自动建图」。这会停止普通建图并重新
   建立坐标，启动雷达、激光里程计、SLAM 和 Nav2；不会启用电机。
2. 用「查看探索目标」检查当前地图。算法在已知自由空间内选择观察点，将障碍、未知
   区域和地图边缘按车身外接圆加余量保守膨胀，不把目标设在未知区域。Nav2 再按实车
   转弯约束规划和避障。不足以容纳车身的起点会拒绝探索。
3. 完成真实转角、速度及安装几何核对后，才能由当前驾驶页启用电机并「开始自动建图」。
   地图名使用上方地图英文名。连续三个新地图更新均无有效未知边界时保存地图；仍有
   边界但无新可达观察点、导航失败或超时会停止并明确标为未完成。可手动保存部分地图，
   不会伪称完整覆盖。人工「结束建图并保存」也按提前结束记录。
4. 建图结束停车并解除使能。停止建图管线，加载保存地图并设置真实初始位姿，配置、
   保存巡检点和停留时间，选中任务后点击「执行所选巡检任务」。
5. 每点依次进行导航、实际位置/朝向核对、停车稳定、新帧检测和证据保存，支持有限次数
   循环。检测失败不会跳到下一点；全部处理后停车并由本地模型生成报告。
6. 建图和巡检全程监视已有相机检测。疑似火情或不确定结果立即停止自动任务、解除使能，
   网页显示告警及原始图片；巡检途中告警也纳入本次报告，不冒充已到达下一个巡检点。
   人工确认告警只解除告警显示，不启用电机、不恢复旧任务。

自动任务需要驾驶页保持可见且连接正常。等待检测和停留阶段同样检查驾驶权、600ms
操作者续约、雷达、定位和相机结果；数据失效或人工接管均锁定停止。单目标限时2分钟、
单任务限时20分钟、探索最多200个观察点。服务重启恢复记录，任务标记中断，不恢复运动。
相机检测是模型周期推理，存在推理延迟，不等同实时火灾传感器；不做自动灭火或自动返航。

`data/autonomy/` 保存任务状态和异常图片/JSON（Git 忽略），`data/inspections/` 保存巡检报告。
`autonomy_runtime.py` 负责串联既有 Nav2 和检测服务，`frontier_explorer.py` 为离线可测试的
探索算法。告警通过当前网页 SocketIO 广播，未发送到外部消息服务。

新增验证：导航/任务70项、检测报告21项、驾驶128项及三组前端验证通过。使用替身的
任务测试覆盖到点检测、末点不确定结果、迟到回调、失联停车、超时、重启和告警归档。
板上 `autonomy_smoke.py` 已验证 SLAM 与 Nav2 同时输出真实数据、探索预览和未标定拒绝
